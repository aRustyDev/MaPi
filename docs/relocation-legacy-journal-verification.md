# Legacy relocation journal verification

Use a private checkout with the pinned Nextgen source and dependencies prepared by the repository build. The test creates a fresh local Workerd state directory, generates a temporary master key, provisions synthetic projects through the Go/Wasm owner, and deletes the temporary state on normal exit. The test worker only accepts requests from the loopback HTTP address with its local-test flag enabled.

1. Build the pinned owner and baseline with `bash scripts/build.sh` and `npm run baseline` when the generated artifacts are absent. Run `node scripts/test-real-relocation.mjs`. Allow up to two minutes for the local request. A completed run exits zero and reports 59 reconciled tables, one synthetic user, audit rows, rejection of legacy journals, and rejection at the archive gate.
2. Confirm the coordinator advances through import and transfer-history verification before reconciliation. The test checks the final history checkpoint, chunk count and digest. The last history page and first reconciliation page can complete in the same coordinator call.
3. Confirm a partial version 2 journal and a complete version 2 journal are each rejected by reconciliation, commit and coordinator retry. Repeat after registry eviction. For each rejection, the test compares the journal checkpoint, evidence count, transfer-history checkpoint, registry route, source fence and staged destination with the state captured immediately before the call. The second synthetic project remains active.
4. Confirm the current journal reaches reconciliation, then the archive gate rejects cutover. The route stays moving, the source stays frozen, the destination stays staged, and the checkpoint, evidence and history remain unchanged. The harness creates a committed historical fixture only after checking that gate. Use that fixture to verify an unfinalized legacy committed journal rejects activation, retirement, finalization and coordinator retry, including after registry eviction. A finalized historical move remains readable and retryable.
5. Record the command, exit status, synthetic counts, commit and the exact failed assertion if any. If a build, local listener, test, or eviction check cannot finish, mark the corresponding checklist item incomplete and identify the blocker. A timeout or skipped assertion is an incomplete result. Do not include Woven object identifiers, database contents, audit counts, credentials, or private source-audit observations in public reports.
