# Pinned credential transfer: local Workerd

`node scripts/test-relocation-credentials-workerd.mjs` passed on disposable local Workerd SQLite objects. The test creates the pinned `projects`, `users`, `user_attributes`, `auth_attempts`, `user_totp` and `user_passkeys` table definitions in separate source and destination objects for each of two synthetic projects. It interleaves their actual `beginChunkExport`/`exportChunk` and `beginChunkImport`/`importChunk` operations. Local user, handoff, TOTP and passkey identifiers overlap, with different synthetic credential bytes for each project.

The test compares the SQLite storage class, byte length and hex content of the selected credential BLOB columns, including empty and NULL values, between each source and its destination. It checks both destinations for foreign project rows and foreign-key violations. For a `user_attributes` chunk it injects failure after one inserted row and verifies rollback of the row count and import checkpoint, then imports and replays the same chunk and verifies unchanged count and checkpoint.

This is a small sequentially interleaved test of the chunk helpers, not a concurrent-traffic test. It does not exercise real application owners, authorization, registry routing, source or destination restarts, cryptographic key recovery, historical audit reconciliation, an independent source commitment, all table or value types, full-size rows or the 128 MiB fixture, or a hosted staging move. It does not establish that the move is safe. The fault injection and source data are synthetic; no Woven deployment or AWS resource was changed.
