# Local OIDC discovery egress spike

This proof is **local-only**. It has no production ingress or arbitrary-provider transport and has not been deployed. It runs pinned Nextgen Go `idp.ParseConnection` and `idp.NewOIDCClient` inside a small Wasm reactor. The first Go call invokes the actual OIDC relying-party construction with a non-networking `RoundTripper` that captures its discovery request. After the host obtains a bounded response, a second Go call replays that exact response through the same upstream constructor, including its issuer and discovered-endpoint validation. The replay transport cannot dial a network.

The SQLite Durable Object validates an operator-fixed, exact **literal loopback HTTPS origin** and asks the upstream Go egress policy to allow that IP only through an explicit synthetic-local exception. It stores an intent and lease in a short synchronous transaction and calls `storage.sync()` before dispatch. It then performs one `fetch` outside any transaction, with no ambient credentials, manual redirects, a one-second timeout and a 16 KiB response cap. After the fetch, another short transaction checks the lease and deadline, resumes Go from the in-memory response, and records only a small result. Retries after an interrupted attempt obtain a new lease; stale responses cannot commit over a newer attempt.

The local test creates a synthetic HTTPS server with a temporary local CA and a signed certificate. It uses the normal TLS verification path and configures that CA only for the local workerd process. It exercises upstream deny-list checks including private, loopback, link-local, IPv6 and embedded IPv4 addresses; exact-origin rejection; interruption before dispatch and after response; persisted retry and eviction; concurrent leases and stale-response fencing; same-origin and downgrade redirects (both rejected); oversized fixed and streaming bodies; incorrect discovery issuer and an insecure discovered endpoint; and timeout. These tests cover only discovery GET, which is idempotent. They do not establish safe retry of authorization-code or token-exchange POSTs, where duplicate remote effects are possible.

After `npm ci` and `bash scripts/build.sh` have prepared the pinned checkout, run:

```sh
node scripts/build-egress-spike.mjs
node scripts/test-egress-spike.mjs
```

The test needs OpenSSL and local loopback listeners. Temporary keys, CA, server and SQLite state are removed on completion. The standalone Wasm measured 18,748,892 bytes; a local dry run of the **test harness** was 18,319.75 KiB uncompressed / 4,871.37 KiB gzip. This is not the combined app size or a hosted CPU, latency, memory or platform-limit measurement. The test harness contains a local control route and fault injection; it must not be deployed.

## Real-provider blocker

The pinned [egress policy](https://github.com/zitadel/nextgen/blob/b0b74cd4a198428ea9b82910c217259ffc62b65c/docs/adrs/061-egress-policy-user-injectable-urls.md) requires checking the **actual connected IP** after DNS resolution, on each connection and redirect. Checking a hostname or resolving it before `fetch` does not prevent DNS rebinding. This spike avoids DNS by allowing only the fixed local literal IP; it intentionally refuses all redirects, whereas the upstream policy permits bounded, revalidated redirects and prevents HTTPS downgrades and credential leakage. It is therefore a **strict subset, not egress-policy or redirect parity**. Workers' Node HTTP implementation is a `fetch` wrapper that does not support a custom `lookup` or `createConnection` hook ([Cloudflare Node HTTP documentation](https://developers.cloudflare.com/workers/runtime-apis/nodejs/http/)). A real-provider design must establish a trustworthy dial-time IP check, TLS hostname verification, bounded redirect processing, per-hop egress checks and upstream allow/deny semantics; a DNS precheck alone is insufficient.

Before integrating any real IdP, bind the intent and response to the owning project, immutable connection revision and active flow, revalidate authorization, expiry and revocation in the commit transaction, and implement safe handling of secrets, PKCE, state, nonce, code exchange, JWKS, ID-token validation, account linking, outages and non-idempotent retries. Every discovered endpoint must undergo the full egress policy when used. In particular, the upstream constructor notes that the discovered JWKS URI is not exposed for the same early validation as the other endpoints; this spike does not close that gap. Protect and expire persisted intents, avoid logging credentials and provider bodies, bound concurrency and overall multi-request deadlines, and test crash, restore, replay and provider key rotation. A secure proxy or another execution environment is only a candidate until it proves these constraints and the project's Workers-first acceptance gates.
