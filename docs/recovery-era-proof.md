# Isolated recovery-era proof

`node scripts/test-recovery-era.mjs` starts a local workerd with separate SQLite-backed registry and project objects. This is a test-only model; it is not connected to MaPi ingress, restore, relocation, or the split password verifier.

The registry starts each recovery with a fresh random era and refuses active routes while recovery is underway. The project checks both the authoritative registry and its local era before admission. The test suspends a synthetic verification, fences the registry and owner, simulates a restored database containing the old active era, and verifies that neither the old route nor the new route can be used during recovery. Reconciliation deletes the synthetic sessions and handoffs and installs the new era before the registry reopens. The old route and suspended verification remain rejected, including after object eviction. Concurrent recovery attempts are rejected.

The simulated restore writes old values into the running test object. It does **not** exercise Cloudflare PITR or prove its exact concurrency, abort, or restart behavior. Cloudflare documents that PITR restores the entire object storage on the next session and is unavailable in local development; it normally requires aborting the object to restart it. A real protocol must stop admission, freeze and drain the owner, schedule the restore, restart it, and ensure no pre-restore invocation or cached authority survives. It also needs authenticated and idempotent control operations, interrupted-operation recovery, a durable authoritative registry that is not rewound with the project, relocation fencing, and an explicit process for registry recovery. Registry lookup and object mutation are not a cross-object transaction: a route can change after lookup, so the owner fence and restart/drain protocol are essential. The test does not attempt to prove a delayed registry response spanning an actual restart.

Real Nextgen sessions and handoffs, mutation audit, recovery-era ownership, revocation policy and project state are not wired into this model. No hosted restore, external-epoch backup, race with production ingress, observability, load, or security review has been done. A hosted PITR rehearsal and the complete end-to-end recovery and relocation tests remain necessary before this can protect real data.
