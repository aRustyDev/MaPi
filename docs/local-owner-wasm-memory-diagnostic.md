# Local owner Wasm memory diagnostic

The disposable Miniflare routing diagnostic now samples `/_mapi/admin/status` after each warm wave when run with `--load`. It validates sampled byte/page consistency, records the owner's boot marker and reactor-initialization count, and reports the largest observed linear memory and the owner's request-boundary high-water mark. Status is sampled after the timed journeys have completed; its time is included in overall throughput and reported separately. It is not a cold-start measurement: status can initialize a reactor, so the diagnostic does not call it before the warm waves.

In `/private/tmp/mapi-owner-progress26-oPQU0c`, `node scripts/test-current-owner-routing-miniflare.mjs --load` passed both five-wave, two-project runs with 20 legacy password-login-plus-session journeys per project. For both projects, each run obtained five status samples from one observed boot marker and reported **106,168,320 bytes, or 1,620 64-KiB pages**, for both the largest sampled linear memory and the owner's high-water mark. The largest observed reactor-initialization count was two per owner. Plain local journey p95 was 2,170.47/2,170.72 ms, with 3.72 journeys/s and 11.08 ms spent on status sampling. With 40 interleaved management reads, local p95 was 2,226.21/2,226.38 ms, with 3.66 journeys/s and 8.35 ms sampling. Timings include a session read and do not use the hosted browser-to-RP endpoint.

The tested bundled JavaScript SHA-256 was `9ab027c7915ca28c354cc1f9b4af807f2e54a6a2357040b5775e5451ac212cc6`, Wasm SHA-256 `b67b6e6341c2598917575a486d61dc91e7b6f8b1f6a7c4fcfdc96c68146939e2`, chunk importer SHA-256 `8f30191903d60bc6d01bd4f4afc1d62653950e956b9db3f745db4af091d9527a`, and diagnostic script SHA-256 `21a3ceb96cea7972501841d3523d78e52b8daa4c0575473d130173ac69f1ff01`. This dirty local bundle predates later control-table changes.

Linear Wasm memory is not total isolate memory. The owner high-water is sampled at reactor initialization and request boundaries, not continuously; an eviction or failed call could change coverage. This run does not measure platform CPU, total isolate memory, platform limit errors, browser/RP behavior, hosted cold starts, concurrent operator writes, or the selected final candidate. It does not replace the hosted gate or establish independent recovery. No Woven deployment or AWS resource was changed.
