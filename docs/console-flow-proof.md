# Official Console password flow: isolated local proof

This local-only Worker combines the actual v0.7.0 Console assets, the real per-project runtime bootstrap and authoritative session-read proof with the existing upstream flow proxy and an opt-in `mapi_flow` reactor. It has no production ingress or deployment. From MaPi, after building the Console and empty baseline as described in [console-static-investigation.md](console-static-investigation.md) and [console-runtime-proof.md](console-runtime-proof.md), run:

```sh
MAPI_CONSOLE_DIST=/private/tmp/mapi-console-proof/apps/api/internal/staticui/console/dist node scripts/build-console-static-proof.mjs
GOPROXY=off GOMODCACHE=/private/tmp/zitadel-nextgen-poc/go-mod GOCACHE=/private/tmp/zitadel-nextgen-poc/go-cache node scripts/build-console-flow-proof.mjs
node scripts/test-console-flow-proof.mjs
```

The test provisions two separate local project objects, creates a synthetic user, loads the real Console, and completes the official `<zitadel-login>` identifier and password steps. The component exchanges a handoff through the upstream Go handlers, receives a real HttpOnly session cookie, reloads, and reads the session from its owner. It rejects a wrong password, a replayed handoff, a flow cookie at the other project, a session cookie at the other project, foreign or missing POST Origin, foreign project IDs, duplicate session project IDs, unsupported methods and an oversized flow request. The browser made no requests to another origin in this test. Backend egress was not independently instrumented. The test prints no credential, handoff, cookie or token values. The Go reactor is 54,211,637 bytes, excluding Worker JS and static assets; this is not a hosted capacity measurement.

**The account-enumeration gate fails.** The pinned default flow intentionally sends a known email to the `password` step and an unknown email to the `register` step. Both identifier responses are HTTP 200, but their JSON step names differ. The component visibly shows `Continue with password` and no password field for an unknown email; a wrong password for a known account displays `Wrong email or password.` Thus the responses and UI reveal account existence before password verification. Five warm local samples from one run measured identifier submit times of 39–50 ms (median 41 ms) for known and 40–43 ms (median 42 ms) for unknown; another run measured 40–56 ms (median 46) and 39–56 ms (median 44), respectively. These small browser-to-response samples are not a side-channel assessment and do not cover password-verification work. A mitigation must equalize the visible flow **and** API response and address equivalent password hashing, abuse controls, races, and timing before the original same-error gate can pass.

The Console calls `/api/v1/flows` and `/api/v1/sessions/exchange`; the harness rewrites those paths to the existing `/__nextgen` proxy. That proxy strips browser bearer credentials and the owner injects its project credential for the exchange. This is the existing prototype mechanism, not proof that the upstream publishable-key exchange contract is preserved. The official component receives the one-time handoff in browser flow JSON before exchanging it; it is not entirely server-side. The runtime publishable key was verified separately as project-scoped and read-only, but this flow harness does not use it for exchange authorization.

The Console's login flow is functional only for the tested synthetic journey. Logout, CSRF, management and delegated authorization APIs, platform identity behavior, project relocation and registry-generation fencing, correct upstream publishable-key use, throttling under load, and complete native comparison remain open. Post-sign-in Console management screens cannot function because their APIs are intentionally unavailable. The runtime's unprovisioned 503 and per-origin project choice also differ from native standalone semantics. The test-only operator and session endpoints must never be deployed. No hosted execution, full Console suite, conformance, production security review, or platform-capacity gate is claimed.
