# Leased audit ordering: local Workerd integration

`node experiments/audit-snapshot/shadow-leased-sort-workerd-test.mjs` passed on disposable local Workerd with Go 1.26.9. The test connects the retained Go external-handle sort and SQLite spool to the reusable unmounted `compareLeasedShadowEvents` adapter and actual `readShadowOrderFragment` helper: every timestamp and ID fragment is read through the existing fenced shadow-reader lease. It compared 36 synthetic handles with an independent Go slice-order oracle in ascending and descending order, including signed timestamp extrema and long shared ID prefixes. It made 349 comparisons and returned fragments no larger than 32 KiB. It also rejected a foreign-project handle and a released lease, and rolled the spool back after an injected comparison failure following a swap.

The run used `shadow-leased-order-compare.mjs` SHA-256 `520ceb904926881f556694bf791bbb5242014cecd0697a4f06eb453d85854797`, `shadow-order-fragment.mjs` SHA-256 `51791b97786c09f2e9840f14352687e8df6a9bbab35d58d8dc58c27cf8739076`, `shadow-lifecycle.mjs` SHA-256 `24da09b7c548e6fc9298b6f48405c52c74c4a5bbe6700eddbd7101e24a6ad7dc`, `shadow-sql.mjs` SHA-256 `d2f9eb42eef817e61749ccb274ffd9586ab542fc7af45b3b3b6f293b2aa2a1ad`, and Go reactor SHA-256 `d49def1a2026e78c9e23800d1bec4525d2ec7db582d8a21f2dc47776c48e77ad`. The reactor is compiled in a fresh temporary path and is not a reproducible release artifact.

This is an unmounted integration diagnostic, using a trusted synthetic authorization callback. The spool is written directly inside a synchronous transaction rather than through a protected resumable sorting protocol. Its complete candidate selection, total work and storage, synchronous duration and SQLite-internal memory remain unbounded. Lease position and sorting state are not independently authenticated. The test does not establish full upstream selection, pagination or error behavior, real caller authorization, response or payload fidelity, malformed SQLite TEXT, a complete snapshot, hosted behavior, or the pending handler and interrupted transfer tests. No Woven deployment or AWS resource was changed.
# Resumability boundary

The current diagnostic calls Go's `sort.Sort` synchronously over a directly written spool. Its leased comparator bounds each returned ID fragment but can read all fragments of two long IDs during a single comparison, and the overall sort has no per-invocation work bound or durable program counter. A safe resumable design needs protected, atomic spool and sort-state checkpoints and must demonstrate pinned `slices.SortFunc` tie behavior; choosing a different sort or top-k reduction without that evidence could change returned order. The local 36-handle result does not establish those properties or authorize publication.
