# Local relocation checkpoint guard

This scratch-tested guard prevents reconciliation journals made by older code from authorizing a new cutover. Newly written journal version 2 requires both source and destination digest RPCs to report the version of the non-finite REAL containment before a page can be recorded. Version-1 partial and completed journals fail closed. The registry rechecks a completed current journal immediately after the owner attestations and before the synchronous cutover. This is a version marker for the local containment, not evidence that REAL infinities are transported losslessly.

For a previously committed but unfinished move, the coordinator, registry completion and direct owner activation and retirement require a current journal. Existing completed historical moves stay routable; repeated control calls only observe an already active/retired fence and do not activate a staged destination or retire a frozen source on legacy evidence. Tests simulate legacy partial, complete and committed-but-staged checkpoints, restart the registry, and keep another project active. They set journal versions back only as a local test hook; there is no automatic production upgrade, thaw or repair path for old evidence.

**The guard does not make already-activated legacy destinations safe.** If an older committed-but-unfinalized destination became active before the guard was installed, the registry route and cached direct calls can already admit writes. Preventing or reconciling those writes requires a separate fenced recovery, complete writer drain and authoritative comparison. No automatic rollback, source thaw, recovery or reactivation is supplied. Before enabling any production move, verify all registry and owner writers have drained old builds; an older owner must not be able to produce or reuse unguarded evidence. Even with guarded pages, the underlying source scan and serialization are not a lossless REAL implementation, and resource, exact-row and hosted validation remain open.

Run `node scripts/test-real-relocation.mjs`, `node scripts/test-relocation-manifest.mjs`, `node scripts/test-relocation-coordinator.mjs`, and `node scripts/test-registry-move.mjs` with disposable local workerd state. No deployed Worker or real singleton is modified by these tests.

The older standalone coordinator test had stopped at provisioning after the pending-owner changes because its synthetic registry lacked the owner binding. Its local config now binds the synthetic owner under the expected name, and the owner implements a checked, fixture-only provisioning attestation and activation. Its existing isolation, interruption, rollback and replay assertions remain. It still exercises the older synthetic coordinator model, not the production coordinator; the real-owner test covers the integrated guard.
