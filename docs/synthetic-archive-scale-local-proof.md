# Synthetic archive scale experiment

Status: **local archive-only fixture passed** after binding the completed sealing head into verification and restore and updating its injected-fault handling for redacted, uncertain destination errors. This is a distinct archive-only synthetic test. It does not use the real-owner or large-audit harness, any Nextgen schema or Go handlers, a registry, Woven, or live AWS.

Run `node scripts/test-synthetic-archive-scale.mjs`. It generates 1,024 independently chained, one-row synthetic JSON chunks of exactly 128 KiB each, for 128 MiB of encoded source. It writes encrypted archive objects to a fresh temporary filesystem store using a fake KMS, tracks bounded object sizes, uses local SQLite checkpoint heads to exercise interrupted sealing and verification, and restores exact chunk bytes into a separate local SQLite fixture. The fixture compares ordered aggregate SHA-256 digests and source/destination chain/count/byte totals, injects an upload failure, uncertain authority acknowledgements, a transaction rollback and a lost import acknowledgement, and records resumed cursors and local throughput. Destination failures are intentionally redacted; the fixture identifies its own injected fault and confirms the durable cursor after reopening rather than inferring whether a transaction committed from the error.

On the local run the source and destination both contained 134,217,728 bytes across 1,024 chunks, with matching aggregate digest and terminal chain. The largest encrypted object was 109,360 bytes; 14,401 objects occupied 184,988,523 bytes. Sealing resumed at revision 25, verification at revision 33, and restore resumed at cursors 384 and 769 without rescanning the first selector. Wall time was 25.2 seconds, with 195,772,416 bytes sampled peak process RSS. These timings and memory samples describe this machine, not Worker limits or hosted performance.

The evidence is limited to local synthetic behavior. It reopens local bucket and SQLite handles after faults within one Node process; it does not restart a process or demonstrate recovery of its in-memory fake KMS. The filesystem and SQLite authority are under the same local control and do not prove independent custody, a trusted source commitment, write closure, nonrollback retention, hosted R2 behavior or platform memory/CPU limits. The repeated synthetic payload is not representative Nextgen data and contains no real users, credentials, keys, sessions or audit history. This fixture cannot close the representative real-project, hosted runtime, recovery or cutover gates.
