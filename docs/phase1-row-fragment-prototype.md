# Local near-limit row-fragment prototype

This disposable local workerd probe is a feasibility experiment, not an integrated import, migration or authorization mechanism. Run `node scripts/test-phase1-row-fragment-probe.mjs` from the implementation checkout. It starts a local Worker with two disposable SQLite Durable Objects and removes their temporary state afterward.

The source stores one TEXT value of 8,388,520 UTF-8 bytes, including a four-byte character split across a frame boundary, with two exact signed-int64 extrema, a REAL 0.5, NULL, integer-looking TEXT and a binary BLOB in the same row. Its small values are sent as fixed-schema JSON metadata. The source reads the text as BLOB slices; each encoded frame is at most 128 KiB. The target saves each frame and its digest with a durable numeric checkpoint, then assembles the value inside SQLite using a recursive BLOB concatenation before inserting the row. The test checks SQLite storage types and compares every source/destination frame digest.

The test injects an error after a frame insert and after the final row insert, verifying rollback of both data and checkpoint. It checks an identical duplicate after an acknowledged frame, a differently hashed conflicting replay, corrupt content, an out-of-order frame, and confirmed source and destination boot-ID changes after eviction. One local run measured 103 frames, 8,388,520 bytes and 13.51 seconds, including faults, evictions, retries and a full per-frame comparison; that is not a hosted throughput measurement.

After adding a local-only guard, one integrated run timed out after the injected evictions. That version did not identify the stalled action. The next five runs passed in 2.61–2.73 seconds each; the test now reports the action and frame when a request fails. The timeout remains unexplained and the successful repeats do not establish a hosted reliability result.

Limitations: this is one fixed row and schema, not generic typed metadata or arbitrary statements. It does not prove every REAL value, invalid UTF-8, a large BLOB cell, 100 columns, the exact maximum platform-valid row, the Nextgen manifest, indexes, triggers, foreign keys, authorization or isolation under traffic. The fragment digests are not an authenticated hash chain, and the target leaves staged frames in place. It performs no quota, CPU or isolate-memory measurement; recursive concatenation may copy large intermediate values and its peak resource use is unknown. The source is immutable by test construction, without a route fence. Local workerd limits may differ from hosted Cloudflare. No production cap has been increased, and this proof cannot justify doing so.

The live owner also lacks a completed bounded active-route preflight. `RelocationCoordinator.advance()` currently freezes the source before `inspectRelocationSource()` validates its schema and ownership; oversized rows are detected still later during export. A read-only paged scan before the move can identify existing problems, but concurrent writes can invalidate its findings. A proof valid at freeze requires complete mutation-generation coverage or a fresh authoritative revalidation while fenced. A failed authoritative check must remain fenced until an independently reviewed recovery; the existing protocol does not support an unsafe thaw.
