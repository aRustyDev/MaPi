# Wasm diagnostic decode bound

The owner previously stopped accepting stderr writes only after its accumulated diagnostic string reached 2,048 UTF-16 code units. A single larger Go stderr write was decoded and appended in full before that check could take effect. `worker/wasi.js` supplies this callback with a `Uint8Array` view over Wasm memory.

The owner now limits each decoded prefix to four bytes per remaining UTF-16 code unit, at most 8,192 bytes, before calling `TextDecoder.decode`, and caps the accumulated string at 2,048 code units. `node --experimental-vm-modules scripts/test-owner-wasm-diagnostic-bound.mjs` passed against the actual owner request and initialization methods with a fake reactor and synthetic storage. It checks normal fatal-error classification, a 1 MiB first write, a repeated 1 MiB write after the buffer fills, and multibyte input. The instrumented decoder did not receive a chunk over 8,192 bytes. `node --experimental-vm-modules scripts/test-owner-reactor-markers-native.mjs`, `node --experimental-vm-modules scripts/test-legacy-body-boundary.mjs`, `node scripts/test-runtime-diagnostics.mjs`, and `node --check worker/app.js` also passed.

The bounded prefix may truncate an incomplete UTF-8 sequence or a UTF-16 surrogate pair, and can omit a later fatal marker entirely. A missing marker does not establish zero memory, CPU, or overload errors. The test does not measure isolate memory, exercise real Go stderr, test hosted logging, or validate the final candidate. Earlier real-Go Workerd marker evidence in `reactor-attempt-markers-local-proof.md` predates this application change. No Woven deployment, AWS resource, pending cold-restart test or stopped integration action was touched.
