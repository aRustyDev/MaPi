# Local schema migration proof

The private registry schema-migration RPC supports the existing v1-to-v2 runtime migration. A separate control token, explicit enablement, and an operator assertion that older writers have drained are required. The registry checks the active project route, generation, owner identity and recovery epoch. It records a durable reservation that interlocks relocation and recovery; v1 traffic can continue until the owner atomically adopts and freezes its fence while applying the schema change. The registry then publishes generation `g+1`, the owner confirms that route and activates its `g+1` fence, and the registry completes the migration. Old `g` calls fail after activation. During a lost activation acknowledgement, `g+1` calls are accepted only after that generation is the authoritative active registry route; competing recovery and relocation remain blocked until completion.

Existing v1 and v2 owners can operate under Worker-wide target 2. A reserved fresh relocation destination starts at the v1 baseline so manifest preparation can reproduce the source version and schema, rather than applying the Worker's target before import. This does not independently attest the safety of other future schema versions.

`node scripts/test-schema-migration.mjs` exercises legacy and fenced v1 owners, wrong credentials and routes, transactional DDL rollback, lost apply and activation acknowledgements, owner and registry eviction, direct old and new generation calls, maintenance interlocks, and unchanged project/user/audit data. It also exercises Worker-wide target 2 with concurrent v1 traffic while v1 and v2 projects each move to a fresh destination. The test's fault hook is injected only into a generated local test owner. The pending-owner, recovery-epoch, pre-freeze, real-relocation and relocation-manifest suites also pass locally.

This proof is not hosted evidence or authorization to change a deployment. Before enabling the control, inventory the actual singleton's schema, origin, ID, epoch, keys and deployed writers; verify its independent backup and drain every old writer. The drain flag records an operator assertion and does not perform a drain. A durable incomplete migration has no automatic abort/reset and must be resumed or separately repaired. Recovery reopening is not enabled.
