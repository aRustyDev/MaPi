# Shadow ID external sort: local Workerd diagnostic

`node experiments/audit-snapshot/shadow-external-sort-workerd-test.mjs` passed in a disposable local Workerd SQLite object. It builds the retained `DiagnosticExternalHandleSort` code with Go 1.26.9 as a WASI reactor, connects its get, swap and compare calls to a SQLite handle spool and the actual `compareShadowEventIds` fragment reader, and runs it against an experimental copy-on-write shadow snapshot. A separate native Go 1.26.9 oracle uses `slices.SortFunc` and the pinned event code's `cmp.Compare` ID tiebreaker. All events in this test have equal timestamps.

For 35 synthetic source events, including two distinct TEXT/BLOB keys with equal bytes, Unicode and 70,000-byte common prefixes, the complete output permutation matched the Go oracle. A source delete and a later insert occurred after snapshot creation. The sort made 141 comparisons and the largest returned ID fragment was 32,768 bytes. The diagnostic also rejected a foreign-project handle. An injected comparator failure occurred after at least one successful swap; the spool's synchronous transaction rolled back to its original order.

This is an **unmounted diagnostic**, not a production sort or bounded complete snapshot. The test uses a synthetic `allow` callback, and the sort transaction accesses its test spool directly rather than using the lifecycle's read-only callback; acquiring a reader lease does not authorize those writes. It does not exercise the public Go handler, token or claims authorization, timestamps, indexed/unindexed filtering, pagination, retention interleavings, original payload bytes, serializer, complete transfer, or the interrupted handler and transfer tests. It stores all candidate handles and sorts synchronously, so total work, SQLite internal memory, storage, query duration and interruptibility are unbounded. It does not test malformed SQLite TEXT or SQL/platform boundary limits. Its single local Workerd result and a source-specific Go implementation do not establish hosted behavior or tie-permutation equivalence across toolchains.

The reactor is compiled in a fresh temporary path without `-trimpath`, so its digest is not a reproducible release artifact. No existing Woven deployment or AWS resource was touched.
