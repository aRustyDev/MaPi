# Local Go audit read after relocation

This is a disposable local proof using the pinned Go `mapi_events` handler in an event-capable flow and management test build. It does not expose event ingress on the selected Phase 1 owner or deploy to Woven. The event-capable Worker was previously measured above the 55 MiB budget; this test does not waive that gate or establish hosted runtime evidence.

Run `GOCACHE=/private/tmp/mapi-phase1-go-cache node scripts/build-audit-relocation-test.mjs` followed by `node scripts/test-audit-relocation.mjs`. The build transforms the existing local real-owner relocation worker under `worker/generated/`, so the local-only test exercises the same registry, owner, snapshot, recovery interlock, interruption and relocation code. It issues project credentials through the Go token service using a test-only owner hook. The fixture directly inserts one team and project assignment per synthetic project solely to satisfy the Go event handler's claimed-project visibility requirement; it does not test the real claim workflow.

The test records all pre-move event IDs from source SQLite, calls the Go list handler and verifies the exact set with no extra page, and reads the real `user.created` event by ID. After relocation it checks raw source and destination table evidence and compares the complete Go list and event response structurally, recursively sorting JSON object keys but preserving array order and types. It verifies a second project can read only its own events, and that each project's credential cannot read the other object's audit history. One local fixture contained 18 pre-move events; four repeated runs passed the structural comparison, and a further instrumented pass observed a difference in raw JSON object-key order while the parsed values, event order, exact ID set and raw table evidence matched. The runner uses a one-page fixture, not a large audit dataset.

The response comparison uses JavaScript JSON numbers, which do not independently prove exact 64-bit JSON-number preservation. The separate raw SQL evidence uses the typed bridge representation; the remaining exact-size `RETURNING` and bounded-result gaps are documented in `sqlite-bridge-matrix.md`. This proof does not establish a hosted Go audit endpoint, production authorization, request-audit parity, live project extraction, or use of the current production-sized artifact. The generated test owner contains test-only hooks and must never be deployed.

## Representative local dataset and Go reads

On November 23, 2026, a separate disposable copy at `/private/tmp/mapi-large-audit.9IeXTm` ran `MAPI_LARGE_IMPORT=1 caffeinate -s -i node scripts/test-large-real-relocation.mjs` with a loopback-only listener, isolated temporary Wrangler state and fresh synthetic credentials. The copy was taken before the concurrent registry validator change; it was dirty, used a symlinked `node_modules` and a symlinked pinned Nextgen Git checkout, and its dependencies were not frozen. The listener and local mode do not themselves prohibit outbound network access. No hosted deployment or production generated artifact was changed.

The exit-zero run seeded 10,000 users and 100,000 `user.created` audit events (100,038 historical events total), transferred 180,370,565 encoded bytes in 2,102 chunks, and reconciled 67 tables and 2,100 digest pages with zero foreign-key violations. The move took 103.60 seconds; maximum chunk size was 111,287 bytes. It checked real credentials and active/revoked sessions, a post-move signature using the original issuer key, stale-source rejection, concurrent second-project sessions, interruption, replay and a lost acknowledgement. The test obtained the first two ten-event ascending cursor pages and the final seeded event through the real Go audit handler before and after the move. It required all sampled events to have the expected synthetic project, event type and payload, and compared the responses structurally. A credential from the other project was rejected by the moved project's audit endpoint.

These are sampled Go reads, not a traversal of every event through the handler. The seeded events reuse the same 1,400-character attribute value and refer repeatedly to 60 users; bulk password hashes and salts are also shared. The source and destination digest pages cover the reconciled stored rows, but do not prove exact 64-bit JSON-number preservation. The test directly installs synthetic team assignments for audit visibility and does not establish production claim or authorization parity. It does not prove the latest code, final hosted behavior, a still-valid handoff over this long move, platform row limits, lossless non-finite values, or coordinated recovery. The combined event test Worker is not a deployment candidate and its size is not accepted for Phase 1.

Work on the requested MaPi event-read fix uses an event-only build that augments the pinned source event generator with a separate read-only MaPi catalog, without adding MaPi webhook declarations. An initial disposable build using Go 1.26.9 and task-specific module/build caches passed the upstream event-generator tests, regenerated both Ogen server and Go client, restored handwritten MaPi adapters after `--clean`, and built the event+OAuth test reactor. The missing pinned Go dependency was retrieved into the task cache; existing module archives were read only. That initial build predated the payload-loss guard and did not establish unfiltered handler or bundle coverage. The later results below supersede those initial limitations. No hosted or production event ingress is authorized by this local work.

A subsequent isolated build added the payload-loss guard and passed native generated-union round trips for all 27 catalogued types, zero and false values, exact int64 extrema, null/empty/populated arrays and both recovery-completion shapes. Tests also rejected unknown data, duplicate object keys and malformed Unicode; upstream normalizes an empty stored payload to `{}` before this guard, so this is not raw-byte preservation. The first test attempt used the wrong Go test package name and failed at setup; after correction, the build and test passed. A final stronger test confirmed that Ogen decodes and re-encodes a duplicate key before the guard rejects the resulting data loss.

The strengthened local real-handler fixture passed with 64 users and 512 seeded events. It read the first unfiltered descending page containing a MaPi signing-key event, compared the direct GetEvent response structurally before and after relocation, read two filtered seeded-event pages and rejected both cross-project credentials. It injected unsupported fields, duplicate keys and an unknown type into disposable state: GetEvent and list rejected them without exposing the payload sentinel, then the fixture removed its injected rows and checked project and audit counts. This does not establish unfiltered traversal of all pages or atomic cancellation behavior. These results use an event+OAuth test reactor larger than the production budget, and do not prove a coherent embedded OpenAPI bundle or hosted behavior. The guard parses and materializes the whole payload and has no independent payload-size or nesting-depth bound; the bridge's bounded-result gap remains open.

The affected source emits several distinct OAuth audit types: key rotation, code issuance, refresh reuse, client-credential rotation and revocation, logout-URI registration, and profile-client assignment. FAPI source also emits signing-key rotation, access validation, token exchange, code reuse, resource-policy update, client-key change, assertion acceptance, nonce issuance, PAR pushed/consumed and login started/code issued/login denied. The catalog also covers six recovery-batch invalidation types and both legacy and newer recovery-completion payload shapes; it does not enable recovery. Payloads differ: for example logout registration includes `uri`, profile assignment includes `profile`, and FAPI policies include audience, scopes, enabled state and version. The pinned OpenAPI event discriminator and generated union have no MaPi variants. Preserving each type and payload needs explicit source OpenAPI variants, regenerated server and client types, and authorization, payload, pagination and compatibility tests. The pinned OpenAPI instructions prohibit hand-editing generated code. The user chose to fix the variants needed for unfiltered Phase 1 audit reads; broader event and management parity belongs to later roadmap phases. Renaming an event or dropping unknown records would conceal history. The current production Phase 1 owner does not mount this experimental event handler.
