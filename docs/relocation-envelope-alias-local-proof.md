# Local relocation chunk envelope snapshot

`importChunk` previously hashed `envelope.content` across an asynchronous digest call, then reread the caller-owned `content` and `digest`. A same-isolate native SQLite test changed the content after the call began but before the digest completed. Before the fix the importer committed the changed project name while recording the original content's digest. The source owner normally returns the envelope over a private Durable Object RPC, which detaches the value; this reproduction does not establish that a real owner caller can mutate it or that any deployed project was affected.

The importer now copies both primitive fields before its first `await` and consistently uses those copies for the size check, digest verification, parse, replay check, checkpoint, and staged fence. `node scripts/test-import-envelope-alias-native.mjs` passed for content mutation and an identical replay whose caller mutates the digest. `node scripts/test-relocation-credential-types.mjs` also passed. A disposable local Workerd run of `node scripts/test-relocation-credentials-workerd.mjs` passed with a receiver that mutates its local envelope after starting import; it compared the source and target project name as well as the existing two-project credential, rollback and replay checks. Its `worker/relocation-chunks.js` SHA-256 was `8f30191903d60bc6d01bd4f4afc1d62653950e956b9db3f745db4af091d9527a`.

This test uses small synthetic rows. It does not cover the deferred exact-size, nonfinite, cursor, sequence, scale, real-owner, registry or history-integration cases, nor independent archive proof, full reconciliation, restart, hosted behavior or real cutover. No existing Woven deployment or AWS resource was changed.
