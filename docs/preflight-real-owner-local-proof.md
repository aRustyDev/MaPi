# Real-owner preflight counter experiment

This unfinished local experiment does **not** authorize preflight or relocation. `scripts/test-preflight-real-owner.mjs` constructs a test Worker in memory with in-process Miniflare, fresh synthetic credentials and ephemeral local SQLite state. It bundles the current JavaScript owner with the existing prebuilt `worker/generated/phase1-owner.wasm`; that Wasm and the installed dependencies were not rebuilt or frozen for these runs. The test verified the module exposes the required flow, provisioning, user and OAuth exports. No Worker entry or deployment configuration was created. The local listener and Miniflare do not enforce outbound network isolation, and interruption cleanup is not independently verified.

The command was `env -i PATH="$PATH" TMPDIR=/private/tmp node scripts/test-preflight-real-owner.mjs`. The first attempt using the default sandbox failed before startup because the loopback listener returned `EPERM`. Two subsequent attempts with loopback access, an otherwise empty environment and no Cloudflare credentials reached the real owner and exited with HTTP 500 in the issuer phase. Before that failure, the test had verified that installing the local prototype covered the currently observed tables, that real Go user creation advanced the prototype counter for user and audit writes, that an injected audit failure rolled the counter and rows back, and that a real JavaScript flow-throttle write advanced it. These are observations from a failing test, not a passing end-to-end preflight proof. The expected injected audit error produced SQL text with placeholders and synthetic Go diagnostic identifiers in local output; no real project data or credentials were used.

The issuer phase was not separated into call versus assertion in those completed runs. An attempted targeted issuer-source read and a subsequent diagnostic test invocation were aborted before dispatch without a stated reason; neither was retried. The added phase labels were not exercised. The test's later privileged-counter-rewind, frozen-owner and eviction assertions were not reached, and issuer activity, complete writer coverage, protected checkpoint authority, restore-era freshness and bounded pre-freeze scanning remain unverified. The existing separate prototype already demonstrates that privileged SQL can rewind its counter and change an excluded checkpoint; the new real-owner experiment does not supersede that counterexample. The test is not ready to support a safety claim or staging operation.
