# Local relocation source identity checks

The owner pre-freeze admission and both advisory and frozen source-manifest inspections now compare their singleton project and origin identities inside SQLite. `sourceIdentityMatches` requests at most two numeric match indicators from each of `projects`, `mapi_project`, and `mapi_project_origin`; it does not return stored identity values to JavaScript. Each comparison requires SQLite TEXT and explicitly uses `COLLATE BINARY`, preserving case-sensitive matching even if a damaged table has a NOCASE collation. An expected string containing an isolated UTF-16 surrogate is rejected before binding because binding would otherwise replace it with U+FFFD. There is no new length limit on otherwise valid expected identities.

`node scripts/test-relocation-source-identity.mjs` passed against native SQLite and disposable local workerd. It covers all three tables with a NOCASE declaration, exact and case-mismatched text, INTEGER, BLOB and NULL values, absent and duplicate rows, isolated surrogates, valid supplementary Unicode, embedded NUL and 256 KiB text. Valid long identities matched; the mismatched long identity failed. An instrumented SQL adapter observed at most two rows and at most 29 JSON bytes returned by the identity queries. This bounds returned JavaScript values, not SQL engine work or the already-materialized expected RPC input.

`env -i PATH="$PATH" TMPDIR=/private/tmp node scripts/test-relocation-prefreeze.mjs` passed with synthetic projects and expected negative-case and eviction logs. It additionally checks that oversized owner identity, BLOB owner identity and oversized origin are rejected before freeze without changing the owner fence, business rows, audit count or active route; after repair the same move proceeds. The final helper was in this run. `env -i PATH="$PATH" TMPDIR=/private/tmp node scripts/test-relocation-manifest.mjs` passed for 85 pinned and runtime tables across 85 digest pages, including expected negative cases. The manifest run and pre-freeze run included the contemporaneous separate flow-release change and preceded the later staged-history RPC work. The focused test's embedded-NUL assertions were added after the pre-freeze run and passed separately; no byte identity is claimed for later app changes. The previously aborted real-owner rerun was not retried.

For valid Unicode text, SQL binary comparison preserves the previous strict JavaScript identity comparison. For malformed stored UTF-8, SQLite compares underlying bytes: it can intentionally reject a damaged identity whose replacement-decoded JavaScript value would previously have matched. This does not fix or decide the broader invalid UTF-8 bridge issue; the user's choice on that issue remains pending. Recovery-epoch reads, other source control rows, complete bounded preflight, writer drain, hosted behavior and real cutover remain outside this proof.
