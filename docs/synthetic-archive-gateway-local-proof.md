# Synthetic archive authority gateway: local prototype

`worker/synthetic-archive-gateway.js` is an unmounted synthetic-only Worker. It exposes named service-binding capabilities for bootstrap, sealing, verification and read-only recovery; its default HTTP handler returns 404. The Worker holds the binding to the existing synthetic authority Durable Object. No caller authentication, hosted binding policy, deployment or independently administered account is established by the module.

The gateway requires a bounded, canonical JSON policy and a separately configured digest of its exact bytes. The policy includes the complete source commitment, synthetic key scope, wrapped-key envelope digest, and designated sealing and verification job IDs. It derives the archive identities used by the existing archive protocol. Its immutable base-policy digest binds the scope, source commitment, envelope and sealing job; an explicit bootstrap-only registration binds a verifier job to that base and the verification identity. Sealer methods accept only the configured sealer job, verifier methods may read the sealer and operate only on their registered verifier job, and the recovery entrypoint exposes reads only. Bootstrap initialization does not register a verifier implicitly. A separately approved later verifier job can be appended without altering an earlier terminal head.

The revised `worker/synthetic-archive-authority.js` durably checks the base policy and sealing job, accepts only explicitly registered verification jobs, rechecks registration and configuration around asynchronous hashing and within write transactions, and rejects conflicting registration or any CAS after terminal. Initialization rejects a partial or older policy-less authority schema before adding or altering authority tables. The standalone local test seeds the earlier schema, unrelated user data, and residual internal sequence metadata from a deleted low-ID table, then confirms failed initialization leaves each unchanged. Older synthetic prototype authority objects therefore require a fresh object or a separately reviewed migration; no persisted Woven state was changed. Schema-query result limits bound rows returned to JavaScript, not SQLite's internal scan or sort cost.

Run these distinct local checks from the implementation checkout:

```sh
node scripts/test-synthetic-archive-authority.mjs
node scripts/test-synthetic-archive-gateway.mjs
node scripts/test-synthetic-archive-readonly-authority.mjs
```

The two Miniflare/workerd tests passed with local loopback permission. The authority-only test covers concurrent initialization, conflicting and identical verifier registrations, direct unregistered and corrupted registration rejection, a corrupted terminal sealer, CAS races, terminal heads, an acknowledgement discarded after commit, eviction, restart, separate archive objects, and old/nonfresh object preservation. The gateway test uses actual named service bindings and the real authority class; cross-role calls, malformed or oversized policies, changed source commitment or sealing policy in the **same** authority namespace, unregistered verifier jobs, stale heads and wrong archive identities are rejected without replacing existing heads. It then explicitly registers a later verifier and exercises that job without changing the first terminal verification. Attempts to call create or CAS through the real recovery binding are rejected. The first gateway attempt exited before assertions because the sandbox denied loopback; the subsequent approved local run passed. The earlier authority-only proxy-harness assertion and its correction are recorded in `synthetic-archive-authority-local-proof.md`.

The separate Node archive test uses fake KMS, a tiny in-memory archive and plain objects exposing only `read`. It verifies that protected verification and staged restore can use read-only authority contracts, rejects missing, stale or incomplete heads before target callbacks, and confirms that begin/advance operations still require write methods. The real named recovery service binding's denied writes are tested separately by the gateway test; the actual service stub has **not** been passed through the archive restore code, and no real importer or owner was used. None of these tests replaces the interrupted combined workerd or scale evidence.

The same distinct Node test now also simulates a rollback or privileged alteration of each fake authority during the destination's `begin`, `apply`, and `finish` callbacks. All six calls returned the expected authority error after the callback committed its simulated checkpoint. Restoring the original fake head allowed a retry to complete without applying the chunk twice. In the `finish` case the private target already recorded completion before the error: a caller must not interpret that checkpoint or a failed restore as permission to publish. This test uses a private in-memory target, not a service binding, a real importer, independently durable authority, or route activation; it does not establish atomicity between authority and destination or safe recovery from a real rollback.

The base and registration digests do not identify a service principal, establish the truth of an opaque terminal head, authenticate the frozen-source commitment, or create independent custody. A trusted administrator must exclusively control the bootstrap binding, admit only the intended named entrypoint to each caller, prevent direct unauthorized Durable Object bindings, and deploy the correct verifier and immutable policy. The authority, policy pins and archive also require independently enforced nonrollback retention, pre-marker old-writer drain, write closure and staged-destination reconciliation. Privileged code or binding changes, storage rollback, a compromised authorized verifier or a shared administrator can defeat these assumptions. The local tests do not establish them, a representative archive, hosted recovery or cutover; the independent-recovery gate remains open. No Woven deployment, source replay data, live AWS policy or existing key was modified.
