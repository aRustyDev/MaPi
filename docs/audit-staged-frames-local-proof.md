# Audit staged frames: native SQLite experiment

`experiments/audit-snapshot/staged-frames/frames.js` is an unmounted diagnostic fragment store, not an owner snapshot, an API, or deployable code. Its explicit setup creates two tables in an otherwise isolated test database. No Woven resource was accessed.

The helper copies the scope at entry, compares the supplied owner route and recovery era inside each SQLite transaction, and passes the immutable copied scope to a caller-supplied synchronous authority callback before and after asynchronous hashing. The callback must use that copy, not a captured mutable original. It stores nonempty fragments of at most 64 KiB and a SHA-256 chain, with exact retry of only the most recent frame and a sealed head. Reading a frame verifies its digest and link, checks the final frame against the head, and rechecks scope, authorization and fence after hashing. Scope and control fields have explicit experimental bounds; owner identity and epoch comparisons and malformed control/frame values are masked in SQL before transfer. An untrusted caller cannot turn this callback or a caller-supplied principal digest into actual authorization.

On local Node 26.9.0, this distinct command completed successfully:

```sh
node experiments/audit-snapshot/staged-frames/test.mjs
```

The native in-memory SQLite adapter exercised creation, scope isolation, denial and asynchronous callback rejection; invalid and oversized fragments; append, exact retry and conflicting retry; copying mutable scope and bytes before a digest; sealing and linked reads; stale recovery era; a route freeze and authorization revocation during hashing; corrupted frame content, terminal digest and head count; and basic head cardinality. It did not use the previously interrupted combined archive test or any hosted deployment.

## Open boundaries

- No real Go authorization, principal binding, source query, audit event staging, serializer, HTTP response, memory limit, durable retention or access control is integrated. The supplied check and its arguments must come from trusted code and must not mutate storage or schedule later mutation. Its tested denial is a local fake, not production revocation evidence.
- A single-frame read does not establish a complete authenticated history. `appendFrame` only retries the latest frame and rejects older retries. The separate diagnostic below explores a bounded historical reconciliation, but it is not integrated into append or publication and depends on a pinned head, an independent monotonic authority and immutable scanned frames. A storage writer able to change the head and frames together could forge this local chain.
- All control identity bounds, including the 4,096-byte route-field cap, are experimental. They must be reconciled with real route contracts and cannot silently restrict valid production projects.
- Schema integrity is not revalidated on each operation. A newly installed trigger can mutate unrelated owner tables even if the visible spool postconditions pass. The helper assumes its schema and storage are trusted; schema checks and isolation must be designed before integration. Postconditions do not make untrusted SQL safe.
- No bounded cleanup, quota reservation, crash-resumable verification, retention/recovery policy or storage exhaustion behavior is implemented. The snapshot must preserve event and authorization semantics across retention, revocation, move and recovery, without publishing a partial application result.
- The test uses Node SQLite, not the Cloudflare SQL binding, `transactionSync` implementation, Workerd RPC or actual Go handlers. CPU, SQLite-internal memory, isolate memory, Wasm and total Worker size are unmeasured. The helper does not close any Phase 1 hosted or migration gate.

## Bounded historical replay diagnostic

`verified-replay.js` and `replay-authority.js` are separate, unmounted experiments. Given a caller-pinned scoped head, a caller-held HMAC key and a trusted `read`/`create`/`compareAndSwap` authority, the verifier examines at most four 64 KiB frames per advance. It carries an authenticated checkpoint with the target input digest, cursor, previous chain digest and accumulated bytes. Completion checks the matched target bytes, total count, total bytes and terminal digest against the pinned head. Each frame and the head are rechecked around hashing; the wrapper checks authority before and after advancement and rechecks the owner fence, authorization and pinned head after authority I/O. A stale checkpoint is rejected by the authority contract, and a committed but unacknowledged create or CAS can be reconciled by readback. `appendFrame` itself still rejects historical replay: the separate verifier supplies a diagnostic reconciliation path, not a replacement integrated append protocol.

The distinct command `node experiments/audit-snapshot/staged-frames/verified-replay-test.mjs` passed in native Node SQLite. It reconciled a frame after eight later appends, serialized checkpoints between bounded steps, checked fake-authority stale checkpoints and lost create/CAS acknowledgements, rejected wrong keys and scope, a forged cursor, different retry content, missing or modified frames, head changes and in-flight fencing. It also tested head changes after a fake authority committed and recovery from the resulting durable checkpoint. The original `node experiments/audit-snapshot/staged-frames/test.mjs` passed after the added helper exports.

The HMAC only authenticates progress made by a holder of the key. The fake authority is not independently durable, cannot prove rollback protection, and does not establish job registration or custody; replaying a formerly valid checkpoint is unsafe if the real authority itself can rewind or equivocate. The pinned head must come from an independently authenticated source, and the caller must enforce immutable already-scanned frames throughout every continuation: a head that changes and returns to the same value or a previously scanned frame changed later is not detected by this diagnostic. Local before/after checks do not make remote authority state and SQLite changes atomic, and no result authorizes response publication or route activation. The test does not prove crash recovery, secure key management, full-history integrity under adversarial mutation, general producer concurrency, storage quota, real Workerd behavior or production integration. The interrupted archive-scale and combined workerd tests were not rerun.
