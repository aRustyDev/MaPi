# Pending owner prototype (local only)

This scratch prototype defers schema creation for a fresh owner until it verifies a pending registry route and its object identity. It keeps a durable pending marker around Go provisioning and uses a pending owner fence until the registry has accepted an attestation and the owner has confirmed the active route. The local proof exercises interrupted Go commit, lost activation acknowledgement, restart, both HTTP provisioning entry points, and independent project traffic. Recovery requires a read-only active or legacy owner attestation, a durable recovery intent, and a matching owner freeze before recording closure. Recovery and relocation intents interlock. Interruption keeps the source fenced and resumes the same recovery; no reopen transition is implemented.

Pending initialization rejects destination reservation and import metadata before changing schema. Registry reservations reject outstanding or historically used relocation object names, and move allocation excludes existing project routes and move reservations. These checks and their interrupted same-object collision tests are local only.

Existing unfenced owners are not automatically adopted. Their constructors only inspect schema: missing required internal tables or an unsupported schema version fails closed instead of creating tables or applying migrations. **Before enabling this behavior for the actual singleton, obtain fresh read-only inventory of its stored schema version, required tables, identity, origin, data, currently deployed writers and migration configuration.** A subsequent locally tested fenced adoption and schema migration is described in `schema-migration-proof.md`; verify writer drain and rehearse it before any real cutover.

Against disposable local workerd objects, `node scripts/test-pending-owner.mjs`, `node scripts/test-recovery-epoch-guard.mjs`, `node scripts/test-relocation-prefreeze.mjs`, `node scripts/test-app-owner-fence.mjs`, `node scripts/test-relocation-manifest.mjs`, and `node scripts/test-large-real-relocation.mjs` pass. The last command used its small default fixture, not the 128 MiB representative import. The simulated legacy test removes a fence from a local Go-created owner; it does not prove that old deployed writers were drained or replace singleton inventory. This is not hosted evidence, a release candidate, a complete recovery implementation, or authorization to change any deployment.
