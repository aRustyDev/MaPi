# Private upstream SSO callback state bridge

`internal/mapiidpbridge` is an unmounted native proof that invokes pinned Nextgen `FlowSSOCallback.Process` across synchronous steps. The first step consumes a browser-bound upstream SSO state exactly once. When Nextgen attempts outbound HTTP, the transport returns a bounded intent to the trusted host; on each subsequent step it replays only previously supplied responses and suppresses the temporary upstream failure park caused by the missing network response. After the final response, the original Nextgen callback service writes its result and mutation audit through the upstream `AuthAttemptService` transaction. A known egress failure can instead call `Abort` to write the upstream generic failure and audit.

Run the native suite with:

```sh
GOCACHE=/private/tmp/mapi-isolated-go-cache node scripts/test-native-idp-bridge.mjs
GOCACHE=/private/tmp/mapi-isolated-go-cache node scripts/test-idp-bridge-worker.mjs
```

The tests include a migrated native SQLite database and real auth-attempt service, encrypted PKCE state, a real signed ID token and synthetic provider responses. They cover browser binding, ten concurrent state-consumption attempts, expiry and supersession, actual `FlowSSOCallback.Process` across discovery, token, JWKS and userinfo, a single authoritative callback result and audit event, injected audit failure rollback, and a fail-closed abort that records the upstream failure event once. Connection, variable and key-service lookup dependencies in the callback integration are synthetic; the separate state lifecycle uses real SQLite storage and AES-GCM.

The bridge holds the consumed check and transcript in Go memory for the lifetime of one callback. Its HTTP client never dials: the trusted host must enforce the pinned egress policy, destination and DNS-rebinding protections, TLS, strict response limits, redirect policy and deadlines for every intent. It must hold this state in one isolated reactor across asynchronous fetches, never serialize it to a browser, and prevent concurrent or stale resumption. A lost reactor or ambiguous token POST must not be retried using the same provider code. Go strings and transient copies cannot be reliably zeroed. The tagged local workerd probe keeps the Go reactor alive across actual local HTTPS fetches, with real upstream auth-attempt state and result/audit writes in a SQLite-backed Durable Object. It verifies a complete discovery, code exchange, JWKS and userinfo callback and injects a SQLite audit failure to prove that the result and audit both roll back. A wrong browser binding leaves the real SSO check pending and makes no token request. An injected Durable Object abort after the token response leaves the upstream check consumed and no outcome; a durable test-only fence requires a new authorization attempt and prevents a second token POST after eviction. The provider, connection, secret and encryption-key lookups remain synthetic, and the test-only provider receives the issued OIDC nonce through a private synthetic header. One local run observed 39,845,888 bytes of Wasm linear memory; this is not total isolate memory or hosted CPU evidence. The test requires loopback networking and a temporary local CA.

This proof does not implement a public route, the real upstream login UI or public IdP management and deployment routes. Production cleanup/recovery, arbitrary provider DNS safety, real provider integration, hosted resource measurements and security review remain open.

The local workerd suite also exercises a separate case using the real upstream connection, variable, deployment and project-key services. It creates an IdP revision, sets an encrypted project secret, deploys the release so that deployment variables are frozen, then changes the live secret and creates a newer connection revision. The callback still authenticates to the synthetic provider using the original revision and frozen secret. It rejects reads of that revision and deployment's variables under a different, unprovisioned project ID, checks the stored variable, frozen snapshot, IdP definitions and mutation-audit payloads for the synthetic plaintext, and requires configuration audit events. A separate injected IdP-creation audit failure rolls back the connection before any provider request; removing the fault allows the same configuration to be created. `node scripts/test-native-idp-config.mjs` exercises the equivalent native operator API configuration, revision isolation from a separately provisioned foreign project, deployment snapshot, redaction and audit behaviors; the native test does not drive the external callback or inject configuration audit failure.

This is a service-level proof: it does not publish a release containing the IdP pointer or prove the complete upstream operator API, real provider, browser redirect, DNS safety, hosted capacity, or production ingress. The other callback cases still use synthetic configuration dependencies.
