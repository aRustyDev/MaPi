# Local pre-freeze proof

The registry now records a unique durable move intent before asking the selected source to adopt and freeze its owner fence. The source independently reads that intent and the active route, checks its object ID and project identity, and freezes for the same move ID. Only after a matching owner response and a fresh registry check does the registry transition the route to `moving`. A lost response leaves the intent durable and the source frozen; retrying the same move resumes with the same destination. A competing move or recovery cannot replace that intent. Traffic routed before the freeze may finish while the route remains active; after the source freezes, stale and missing owner authority fail closed, including before the registry records `moving`.

`node scripts/test-relocation-prefreeze.mjs` exercises a held source acknowledgement, direct calls with missing and mismatched routes, a competing move and recovery, source and registry eviction, retry, unchanged source rows and audit counts, and a second project continuing to write. `node scripts/test-real-relocation.mjs` and `node scripts/test-registry-move.mjs` pass locally. These tests use disposable workerd state; they do not prove a hosted build or writer drain.

The local HTTP entry test also holds the acknowledgement before the registry records `moving`, and holds admin calls between status and mutation while freezing. User, OAuth and flow administration return no-store 503 while fenced; malformed active requests keep their 400 behavior. The source business and audit counts remain unchanged and another project continues writes. Separate local tests hold login and session calls across the freeze and check no-store 503, unchanged source state and normal active-route responses. Management ingress tests cover moving, recovering and migrating routes, the race between its registry lookups, malformed routes and unknown/pending routes. These are local tests; the updated candidate has not been rehearsed in hosted Woven.

The initial pre-freeze proof did not cover pending-owner provisioning. Subsequent local integration defers fresh-owner schema creation until a registry-checked pending transition and exercises provisioning, retry, restart and activation; see `pending-owner-prototype.md`. A later guarded local schema-upgrade proof is in `schema-migration-proof.md`. Neither change has been validated on a hosted candidate.

Moves that entered `moving` under older code lack a durable pre-freeze intent. The registry rejects their resume, owner-control status, reconciliation and cutover; a missing or mismatched intent is never synthesized. The route remains closed and requires a separately reviewed recovery procedure. This control-plane rejection does not fence a legacy source that never adopted a fence: direct calls to that source can still mutate it. Before any such recovery, old writers must be drained and the source safely adopted and frozen, followed by a fresh export and reconciliation. The upgrade test checks refusal across registry eviction and another project's continued availability. No actual migration is authorized by this proof.

The advisory and post-freeze checks now validate the aggregate revision-clock record using the same nonnegative signed-int64 contract as the recovery anchor. Previously, a negative SQLite integer was accepted at pre-freeze even though the recovery anchor would reject it. The pinned Go writer initializes the aggregate at zero and only raises it. In `node scripts/test-relocation-prefreeze.mjs`, a synthetic `-1` clock is rejected before the fence with the route active, the same durable move intent, unchanged owner fence and business/audit counts, and another project available. The rejection survives owner and registry eviction; after restoring the original clock, retry of the same intent reaches `moving`. Direct workerd schema-preflight cases also accept integer zero and `9223372036854775807` and reject REAL, nonnumeric TEXT and BLOB stamps. Acceptance of zero tests only the clock record; it does not prove consistency with this fixture's existing scopes. The full preflight remains advisory and unbounded in other places, and hosted behavior and old-writer drain remain unverified. Test logs include expected injected failures and evictions.
