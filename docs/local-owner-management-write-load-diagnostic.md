# Local owner workload with management writes

The disposable local Workerd diagnostic `node scripts/test-current-owner-routing-miniflare.mjs --load` now overlaps the mixed workload with one Go-backed operator user creation per project in waves two and four. After each creation, it reads the created user through the Go management endpoint and checks exactly one `user.created` audit record using the owner's private control RPC. The temporary wrapper for that RPC exists only in the local test process and is not a deployed HTTP endpoint. The four creations used synthetic identities; no Woven, AWS or real-project state was touched.

The run in `/private/tmp/mapi-owner-progress26-oPQU0c` passed 20 legacy password-login-plus-session journeys per project in both runs. The mixed run also passed 40 interleaved Go management get/query reads, four operator creates, four follow-up user reads and four audit assertions. The 19th of 20 local journey times was 2,247.43/2,247.72 ms without management and 2,760.58/2,760.63 ms with management and writes. Aggregate completion was 3.62 and 3.30 journeys/s respectively, including status sampling and verification. Each owner supplied five status samples per run; the largest per-owner request-boundary high-water was 106,168,320 bytes (1,620 pages).
