# Synthetic archive authority: local Durable Object prototype

The earlier authority prototype and tests described below have been superseded by an unmounted base-policy and verifier-registration revision. The current code rejects the earlier policy-less schema without modifying it. See `synthetic-archive-gateway-local-proof.md` for the revised contract and current focused test results. The earlier workerd pass remains historical evidence, not validation of the newer schema.

`worker/synthetic-archive-authority.js` defines an unmounted synthetic-only SQLite Durable Object. It is not connected to the archive writer, registry, source, staged importer or a deployed Worker. It was tested only with a disposable Miniflare worker. It does not provide an independent recovery authority.

The caller selects the object by the exact name `mapi-synthetic-authority-v1/<archiveId>`. Initialization pins that 32-hex archive ID and separate sealing and protected-verification identity digests. Every later operation checks the persisted configuration's shapes and that the object ID still matches its archive name. The object permits one sealing job and allows protected verification jobs only after that sealing job has a terminal head; each verification head binds the exact digest of the terminal sealing head. Supported heads have the exact canonical v1 sealing or v2 protected-verification shapes. IDs, role names and digests are length-checked; malformed fields or unexpected properties fail closed.

Each create or compare-and-swap checks the current value and writes its successor in one `transactionSync` callback. The successor must retain the same job and identity, advance revision by one, bind the exact SHA-256 of the predecessor, and preserve any verification seal binding. Once the persisted head is terminal, subsequent CAS operations fail. The object revalidates stored sealing heads before using them, compares its expected schema and exact index inventory with at most one extra row, rejects triggers or unrecognized indexes, and checks write postconditions before returning. SQL projections mask oversized configuration and head values before returning them to JavaScript. This is defensive fail-closed behavior, not a proof against a privileged administrator who can rewrite a valid configuration, replace the code, or roll storage back. Cloudflare documents that SQLite `transactionSync` rolls back when its synchronous callback throws. [SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)

Run `node scripts/test-synthetic-archive-authority.mjs`. It creates fresh local persistence and uses a local test-only Worker with SQL fault-injection and eviction methods; those methods are not present in the authority class. The corrected run passed on 2026-11-23 with local loopback permission. It covers conflicting concurrent initialization, distinct sealing-job creation and same-predecessor CAS; malformed roles and length bounds; forged identities and seal bindings; terminal heads; trigger, oversized-head and invalid-configuration faults; two independent archive objects with overlapping job IDs; a discarded acknowledgement resolved by read; object eviction; and a local runtime restart. The first run exited with a test-harness assertion because Miniflare exposed RPC results as Node proxies. The harness was corrected to serialize results inside its test Worker, and the corrected run exited zero. It does not query, repeat or establish the result of the previously interrupted combined workerd test.

The authority can enforce that a terminal head cannot later be changed through its methods, but the head is opaque: it cannot prove that the verifier actually authenticated all chunks before setting `terminal`. An authenticated, trusted verifier and independently sourced commitment remain necessary. The bootstrap, call authorization, separate administrator and physical account, immutable archive and checkpoint retention, independently held pins, restore reconciliation, and protection against administrative code replacement or point-in-time rollback are not provided or tested here. A well-formed privileged rewrite or rollback of the entire authority state is not detectable by this object alone. The archive's required old-writer drain and write-closed namespace are also unproven. Independent recovery stays open; no Woven deployment, source replay data or live AWS resource was modified.

## Case and TEMP schema guard

A local Workerd regression reproduced a trigger declared on uppercase `AUTHORITY_JOBS` bypassing the binary catalog filter and allowing a job creation with a side effect. This was a synthetic authority-only fixture, not a deployed failure. The guard now compares relevant catalog names without ASCII case sensitivity and also rejects TEMP shadows and TEMP triggers on the authority tables. `node scripts/test-synthetic-archive-authority.mjs` passed on disposable local Workerd, including rejection of the uppercase trigger before any side effect, normal create, compare-and-swap, eviction and restart. The actual authority queries an empty TEMP schema in that run. `node --experimental-vm-modules scripts/test-synthetic-authority-temp-native.mjs` passed with the actual authority class and native SQLite for a TEMP trigger, an uppercase TEMP table shadow, no trigger side effects and normal operation after removal. TEMP object creation and the rejection cases were not exercised in Workerd and may be unsupported there; the Workerd test does not establish them.

The authority source SHA-256 for these results was `f81a1cfe0d3926c3d05717b9ff743a26e6de8ac9b5bc81ce73a8f33aeb6fe6f3`. This remains an unmounted local prototype, and the checks do not establish independent custody, nonrollback, trusted complete verification or cutover authorization. The previously interrupted combined Workerd test and representative archive scale work were not repeated.
