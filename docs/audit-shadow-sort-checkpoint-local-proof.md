# Shadow sort checkpoint: local seam

The unmounted shadow lifecycle now owns private sort metadata and spool tables. Bounded append, swap plus opaque checkpoint, status read and incremental discard each run inside the same synchronous transaction as route, recovery-era, schema, trusted authorization and reader-lease checks. Active sort jobs block reader release and shadow close. A discarded-job tombstone makes a repeated discard acknowledgement safe and prevents reusing the same sort identity before shadow close. Appends accept at most 64 scoped row handles, a checkpoint at most 4 KiB and one swap per transition; discard removes at most 64 rows.

`node experiments/audit-snapshot/shadow-sort-checkpoint-native-test.mjs` passed with native SQLite: it checks foreign-handle and oversized-batch rejection, stale versions, rollback of both swaps when checkpoint update is injected to fail, committed readback, incremental discard and lost-ack retry, reuse rejection, active-sort release denial and frozen-owner denial. The test uses a direct test-only fence reset solely to exercise subsequent shadow close and cleanup; it is not a supported recovery operation. Existing native lifecycle, temporary-schema and main-schema case regressions passed. `node scripts/test-audit-shadow-guards-workerd.mjs` passed the existing disposable local Workerd lifecycle checks after the change; its TEMP fixtures were rejected by SQLite before guard assertions.

The separate disposable Workerd test `node experiments/audit-snapshot/shadow-sort-checkpoint-workerd-test.mjs` exercised the actual new transitions and passed the bounded append, foreign handle and stale-version rejection, injected failure after swaps with checkpoint and spool rollback, release and freeze interlocks, committed swap, lost discard acknowledgement, reuse rejection, and synthetic close and cleanup. Like the native test, it uses a trusted synthetic authorization callback and a test-only direct fence reset for cleanup. It does not test real object eviction or production caller authorization. This is not a sort implementation or authority proof. The supplied checkpoint and swap are opaque instructions from a trusted engine; the seam does not validate pinned Go algorithm or tie semantics, candidate completeness, payload integrity, bounded total sorting, authenticated resumability or real caller authorization. The manifest and spool remain in the same SQLite database and direct SQL access can bypass the protocol. Recovery after actual object eviction remains untested. No production owner, handler, real move, hosted test, Woven deployment, or AWS resource was changed.
