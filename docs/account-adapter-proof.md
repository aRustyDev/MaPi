# Isolated Nextgen account adapter

This is a local test-only build, not a public Worker route. The `mapi_account` Go adapter wires the pinned Nextgen user service, schema store, project hasher and password policy, the original generated request/security/response handlers, and the existing CSRF middleware. It mounts `GET/PATCH /users/me`, `GET /users/me/password`, `GET/PATCH /users/{user_id}`, and `GET/PUT /users/{user_id}/password`, with `/api/v1` aliases. Session-only operations require an authenticated session; the administrative password write uses the upstream `user.write` project credential. The experimental adapter is separate from `mapi_management` and does not modify the production Worker or its ingress.

The pinned OpenAPI has **no self-service password-change mutation**: `/users/me/password` is a read-only state endpoint. `PUT /users/{user_id}/password` is an administrative reset and does not verify the current password. A current-password self-service change would be a separate extension with its own contract, security review and tests; it must not be presented as a pinned upstream operation.

From the MaPi checkout, generate the synthetic local fixture and `.dev.vars.poc` (or reuse the existing ones), then run:

```sh
node scripts/fixture.mjs
node scripts/build-account-test.mjs
node scripts/test-account-parity.mjs
```

The build copies a Git archive of the pinned source into a temporary checkout, applies the overlay and audit patch, and injects its account hook there. It does not change the pinned checkout. The test starts a separate native Nextgen and local workerd, provisions synthetic data, and compares operation statuses and stable error codes. It covers bearer and session authentication, self-project isolation, CSRF and cross-origin rejection, self and admin attribute updates, malformed attributes, password-state reads, rejected credentials, concurrent admin password resets, old/new password verification, session reads after reset and after revocation, and mutation audit counts. Local workerd additionally injects audit failure in both attribute and password mutations and proves the write rolls back; native fault injection is not exercised. The fixture exports a second native project's project, token, key and authorization rows into the same test object. Its foreign credential is rejected by the object-project fence: the native server returned 404 `user.not_found` and the Worker returned 401 `auth.unauthorized`. A separate team test confirms this fixture credential is recognized before the common authentication-attempt project fence rejects it. This is not a second independently owned Worker object; cross-object credential and authorization parity remain open.

In the tested pinned release, admin password reset left an already issued session valid; revoking that session then made the self endpoints return 401. Both testing-kit projects accepted a one-character password, so this fixture does not prove a recommended password policy. Policy/deployment variations, complete response-body and error matrices, request audit parity, concurrent histories under sustained load, other delegated grants, real shared-namespace ingress, hosted execution and production safety remain unproven. The test build measured 54,544,041 bytes of uncompressed Wasm in one local build; total Worker upload size, cold start, CPU, peak isolate memory and hosted limits have not been measured for this slice. Do not expose the adapter until those gates and real ingress security tests pass.
