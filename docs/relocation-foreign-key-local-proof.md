# Local relocation foreign-key result bound

The source inspection, destination preparation and chunk import now use `assertNoForeignKeyViolations` from `worker/foreign-keys.js`. It executes `SELECT 1 AS violation FROM main.pragma_foreign_key_check() LIMIT 1` inside the existing synchronous transaction. The caller-facing violation messages remain unchanged. A successful check materializes at most one returned row in JavaScript; this does **not** bound the work SQLite performs while checking foreign keys or make the broader pre-freeze scan bounded.

Explicit `main` preserves the old unqualified `PRAGMA foreign_key_check` main-schema scope. The function-call parentheses matter: native SQLite showed that a bare `FROM pragma_foreign_key_check` can silently resolve to an empty same-named user table and hide an actual violation. The function-call form fails closed if a same-named main table or view shadows it. It propagates SQL errors instead of treating them as a clean result.

`node scripts/test-relocation-fk-bounds.mjs` passed with native SQLite and disposable local workerd on November 23, 2026. It checks two simultaneous deferred violations in different child tables, composite keys, partial-NULL validity, rollback of inserted rows and a synthetic checkpoint, and a valid retry. It confirms the helper returns zero or one row. On both runtimes, same-named main tables and views caused the helper itself to reject inside the callback, and prior changes rolled back. Both the old PRAGMA and the helper reported the foreign-key-mismatch category for a malformed foreign-key definition. Native SQLite also exercised a temporary shadow and an in-memory attached schema: main qualification avoided the temporary shadow, and both old and new checks ignored a violation confined to the attached schema. Local workerd denied the TEMP and ATTACH probes with `SQLITE_AUTH`; that is the observed local result, not a claim about all hosted configurations. Unexpected capability-probe failures are labeled unclassified, not treated as evidence of platform support or lack of support.

After the shadow-safe change, `npm run test:relocation-chunks` passed with a failed dependency-order import leaving its event rows and checkpoint unchanged. `node scripts/test-relocation-manifest.mjs` passed with 85 tables and 85 digest pages; its logs included expected negative-test errors. A real-owner relocation test passed for the earlier preliminary query before the shadow-safe adjustment. The final real-owner rerun was aborted before dispatch without a stated reason and was not retried; real-owner integration of the final form and hosted behavior remain unverified. The local fixtures are not an authorization to move an existing project.
